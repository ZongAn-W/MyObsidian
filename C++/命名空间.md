# 命名空间（namespace）

> 一句话：命名空间是给标识符「加姓氏」的容器，用来解决**名字冲突**、按模块组织代码。
>
> 记忆：命名空间 = 姓氏，`::` 是「谁家的」，`using` 是「打招呼时省略姓氏」。

## 1. 为什么需要命名空间

C 语言没有命名空间，库函数重名只能靠加前缀来避免，例如 `glfw_init`、`ssl_read`、`pthread_mutex_lock`。这种「手工前缀」的缺点很明显：名字长、容易忘、不同库之间仍然可能冲突。

C++ 项目中的典型冲突场景：

- 自己写的 `log()` 与 `<cmath>` 里的 `log()` 重名；
- 两个第三方库都提供 `init()`、`print()`；
- 标准库的 `cout`、`string`、`vector` 如果全部直接暴露在全局作用域，会严重污染代码。

命名空间的做法：把一组名字装进一个「盒子」，访问时用 `盒子名::名字` 指明来源。

```cpp
namespace math_lib {
    int max(int a, int b) { return a > b ? a : b; }
}

namespace net_lib {
    int max(int a, int b) { return a > b ? a : b; }
}

int main() {
    math_lib::max(1, 2);   // 调用 math_lib 里的 max
    net_lib::max(1, 2);    // 调用 net_lib 里的 max
}
```

## 2. 基本语法

### 2.1 定义命名空间

```cpp
namespace mylib {              // 打开一个命名空间
    int version = 1;           // 变量
    void print(int x);         // 函数声明
    class Buffer;              // 类型声明
    namespace detail {         // 嵌套命名空间
        void helper();
    }
}                              // 注意：结尾没有分号
```

命名空间内部可以放：变量、函数、类、模板、typedef/using 声明、其他命名空间。

### 2.2 访问成员

```cpp
int g_counter = 0;

void use() {
    mylib::print(42);          // 限定名访问
    mylib::detail::helper();   // 嵌套命名空间逐层限定
    ::g_counter = 0;           // :: 开头表示全局命名空间，显式避开同名遮蔽
}
```

### 2.3 同一个命名空间可以多次打开

```cpp
namespace mylib {
    void print(int x) { /* ... */ }
}

// 另一个文件中可以继续往里加东西
namespace mylib {
    void flush();
}
```

### 2.4 命名空间可以嵌套，C++17 起可以简写

```cpp
// C++17 之前
namespace app { namespace net { namespace http {
    void get();
} } }

// C++17 起
namespace app::net::http {
    void get();
}
```

### 2.5 命名空间别名

```cpp
#include <filesystem>
namespace fs = std::filesystem;   // 给长名字起个短别名

fs::path p = "a.txt";
```

注意：**命名空间只能定义在全局作用域或另一个命名空间内**，不能写在函数或类里面。

## 3. using 声明与 using 指令

| 写法 | 名称 | 效果 |
| --- | --- | --- |
| `using std::cout;` | using 声明 | 只把**一个名字**（含其重载集合）引入当前作用域 |
| `using namespace std;` | using 指令 | 把该命名空间里**所有名字**都变成「可省略前缀」 |

```cpp
#include <iostream>

void f1() {
    using std::cout;       // ✅ using 声明：只引入 cout，推荐
    cout << "hello\n";
}

void f2() {
    using namespace std;   // ⚠️ using 指令：引入整个 std，只建议在函数内部使用
    cout << "hello\n";
}
```

### 3.1 最重要的规范：头文件里禁止 `using namespace`

```cpp
// ❌ 错误示范：bad.h
using namespace std;       // 会被每一个包含 bad.h 的 .cpp 继承

// ✅ 正确做法：头文件里写全限定名
#include <string>
std::string trim(const std::string& s);
```

原因：头文件会被大量源文件包含，`using namespace std;` 会把标准库所有名字倒进每个包含者的作用域，造成：

- 自己的函数/变量可能与 `std` 中的名字冲突；
- 调用出现二义性（ambiguous）；
- 编译错误的位置离现场很远，很难排查。

即使是 `.cpp`，也建议把 `using namespace` 限制在函数/块作用域内使用。

### 3.2 别混淆：类内的 using 声明

```cpp
struct Base { void foo(); };
struct Derived : Base {
    using Base::foo;      // 把基类的 foo 引入派生类作用域（解决名字隐藏），与命名空间无关
};
```

## 4. 匿名命名空间

```cpp
// file.cpp
namespace {
    int helper() { return 42; }   // 只在本翻译单元可见（内部链接）
    const char* name = "internal";
}
```

- 没有名字的命名空间，其中的名字自动拥有**内部链接**，只对当前 `.cpp` 可见；
- 等价于 C 语言的 `static` 函数/全局变量，但更现代，还能在其中定义类型；
- 不要写在头文件里：每个包含它的翻译单元都会得到自己的一份副本。

## 5. inline namespace（C++11）

```cpp
namespace lib {
    inline namespace v2 {          // inline 命名空间
        void api();
        int version = 2;
    }
}

lib::api();        // 合法：inline 命名空间的成员可以直接用外层名字访问
lib::v2::api();    // 也合法
```

用途：**版本化 API / ABI 管理**。旧版本 `v1` 保留，默认版本 `v2` 用 inline namespace 提升到外层，调用者无需改代码。

注意：`inline namespace` 和 [[内联函数]] 的 `inline` 是两回事，前者不涉及代码展开，只是名字查找规则。

## 6. 命名空间与 extern "C"

命名空间管「名字的作用域」，`extern "C"` 管「名字的链接方式（是否按 C++ 规则做名字修饰 mangling）」，两者互不影响：

```cpp
#include <cstdio>            // 头文件照常写在文件顶部；<cstdio> 自己已带 extern "C" 保护

extern "C" {                 // 告诉编译器：这段声明按 C 的方式链接
    void c_function(int);    // 声明一个按 C 方式链接的函数
}
```

- 标准库 `<cstdio>` 中的名字在 `std` 命名空间里；`<stdio.h>` 保留在全局命名空间；
- `extern "C"` 不改变作用域：函数的作用域仍是它所在的全局/命名空间；
- 不同命名空间里声明**同名**的 `extern "C"` 函数，链接名相同，会被当作同一个 C 符号，容易冲突，一般不要这样写。

## 7. 常见易错点

| 易错点 | 正确理解 |
| --- | --- |
| 命名空间能定义在函数里吗？ | 不能，只能在全局或命名空间内定义 |
| 命名空间有访问控制吗？ | 没有。它不是类，不能 `private`/`public`，成员全部可访问 |
| `using namespace std;` 能放头文件吗？ | 不要。会污染所有包含者 |
| 匿名命名空间 vs `static` | 都产生内部链接；匿名命名空间还能放类型 |
| 命名空间只能定义一次吗？ | 可以多次打开、分散在多个文件中 |
| `namespace fs = std::filesystem;` 是 using 吗？ | 不是，它是命名空间别名，不会引入名字 |
| `inline namespace` 是内联函数吗？ | 不是，与代码展开无关，是版本化管理手段 |

## 8. 小结

- 命名空间解决**名字冲突**，提供逻辑分组；用 `::` 访问；
- 头文件中禁止 `using namespace`；优先写全限定名或 using 声明；
- 匿名命名空间 = 内部链接，替代 `static`；
- `inline namespace` 用于版本化 API，别和 [[内联函数]] 混淆；
- C++17 支持 `namespace A::B::C` 嵌套简写。

## 关联知识点

- [[内联函数]]：内联函数常直接定义在头文件的命名空间中，需要注意 ODR 规则；
- [[引用]]：标准库中的 `std::move`、`std::forward` 等工具都位于 `std` 命名空间。
