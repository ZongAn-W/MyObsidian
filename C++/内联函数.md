# 内联函数（inline）

> 一句话：`inline` 建议编译器把函数体**直接展开**到调用点，省去函数调用开销；同时它允许函数定义出现在多个编译单元（头文件里），是 C++ 用「函数」替代「宏」的安全方案。

## 1. 为什么需要内联函数

函数调用是有成本的：压参数、保存现场、跳转、返回、恢复现场（完整拆解见 [[函数调用的成本]]）。对只有一两行的小函数，这些开销可能比函数体本身还大。

C 语言用宏来解决：

```c
#define SQUARE(x) ((x) * (x))
```

宏的缺陷：

- 没有类型检查，`SQUARE("abc")` 也能通过预处理；
- 有副作用：`SQUARE(i++)` 展开成 `((i++) * (i++))`，`i` 被加两次；
- 无法调试、无法取地址、容易缺括号导致优先级错误。

C++ 的替代方案：**内联函数**

```cpp
inline int square(int x) { return x * x; }   // 有类型检查，又可能没有调用开销
```

## 2. 基本语法

```cpp
inline int add(int a, int b) { return a + b; }

int main() {
    int sum = add(1, 2);   // 编译器可能展开为 int sum = 1 + 2;
}
```

- `inline` 加在函数定义（或声明）之前；
- 它是对编译器的**建议**，不是命令：编译器可以选择不展开；
- 反过来说，即使不写 `inline`，优化器（`-O2`、`/O2`、LTO）也会自动内联小函数；
- `inline` 真正「保证」的是**链接语义**（允许定义出现在多个翻译单元），内联展开与否由编译器决定。

## 3. 类内定义 vs 类外定义

```cpp
class Point {
    int x_, y_;
public:
    int sum() const { return x_ + y_; }   // 类内定义：隐式 inline
};
```

- 在**类定义内部**定义的成员函数自动是 inline，不需要写关键字；
- 在类外定义时，`inline` 必须写在**定义处**，通常放在头文件里：

```cpp
// point.h
class Point {
    int x_, y_;
public:
    int sum() const;
};

inline int Point::sum() const { return x_ + y_; }   // 类外定义：显式 inline
```

## 4. 头文件与 ODR（重点）

### 4.1 普通函数写在头文件里的后果

```cpp
// ❌ utils.h
int add(int a, int b) { return a + b; }   // 多个 .cpp 包含它 → 重复定义

// a.cpp: #include "utils.h"
// b.cpp: #include "utils.h"
// 链接错误：multiple definition of `add(int, int)`
```

原因：每个 `.cpp` 是一个编译单元（TU），`#include` 是文本展开。两个 TU 都生成了 `add` 的定义，链接时符号重复。

### 4.2 inline 函数允许「多份相同定义」

```cpp
// ✅ utils.h
inline int add(int a, int b) { return a + b; }   // 多个 TU 各有一份，链接器合并
```

- `inline` 函数可以出现在多个翻译单元中，**但每个定义必须完全相同**（token 序列一致，等价于同一个定义）；
- 这属于 ODR 的例外：inline 函数、类定义、模板等允许多个 TU 重复定义；
- 链接器会把它们合并成一份，最终程序里只有一个 `add`。

### 4.3 结论

| 场景 | 做法 |
| --- | --- |
| 函数定义在头文件，多个 .cpp 使用 | 加 `inline`（或写成模板；也可用 `static`/匿名命名空间，但每个 TU 会各有一份） |
| 函数只在一个 .cpp 内使用 | 不用 inline，可以加 `static` 或放匿名命名空间限制作用域 |
| 大的工具函数 | 放 .cpp，头文件只放声明 |

## 5. C++17 的 inline 变量

C++17 起，`inline` 也可以修饰变量，让变量定义可以安全地写在头文件中：

```cpp
// config.h
#include <string>
inline constexpr int kMaxRetry = 3;        // 头文件里定义变量不再需要 static 技巧
inline std::string app_name = "demo";

// 类内定义的静态成员也可以 inline
struct Counter {
    inline static int count = 0;           // C++17：无需类外定义
};
```

- C++17 之前，头文件中的全局变量要用 `static`（每个 TU 一份副本）或 `extern` 声明 + 单一定义；
- `inline` 变量在所有 TU 中是**同一个对象**，地址唯一。
- 注意：需要动态初始化的 inline 全局变量仍可能遇到跨 TU 的初始化顺序问题（静态初始化顺序陷阱），配置项优先用 `constexpr`。

## 6. 编译器到底会不会内联

| 因素 | 对内联的影响 |
| --- | --- |
| 函数大小 | 越小越容易内联；大函数通常不展开 |
| 优化级别 | `-O2` / `/O2` 才积极内联；`-O0` / Debug 通常不内联 |
| 递归 | 一般不会内联 |
| 虚函数 | 通过动态绑定调用时通常无法内联；编译器能做去虚化（devirtualization）时仍可能内联 |
| 取地址 | 函数地址被取走后仍可内联，但要保留一份真实函数体 |
| 异常/大循环 | 降低内联概率 |
| LTO | 链接时优化可以在跨文件场景下内联 |

注意：`inline` 不等于「一定展开」。Debug 构建下断点仍可能停在函数里；想看真实情况可以看反汇编或编译器优化日志（GCC 可用 `-fopt-info-inline-missed` / `-fopt-info-inline-optimized`，Clang 可用 `-Rpass=inline`）。

## 7. inline 与 static、extern 的关系

| 修饰 | 链接性 | 含义 |
| --- | --- | --- |
| 普通函数 | 外部链接 | 全程序一个定义 |
| `inline` 函数 | 外部链接 | 允许多个相同定义，合并为一个 |
| `static` 函数 | 内部链接 | 每个 TU 一份，互不影响 |
| `static inline` | 内部链接 | 常见于 C 头文件；C++ 里一般直接用 inline 或匿名命名空间 |

- `inline` **不改变**函数的链接性（仍是外部链接）；
- 常见错误：只在一个 `.cpp` 里定义 inline 函数，却在其他 `.cpp` 调用 → 其他 TU 看不到定义，链接失败。inline 函数必须在**每个使用它的 TU** 中都有定义（通常放头文件）。

## 8. 内联函数与 static 局部变量

```cpp
inline int next_id() {
    static int id = 0;      // 整个程序中只有这一份 id
    return ++id;
}
```

- inline 函数中的 `static` 局部变量在整个程序中只有**一份**，不会因为多份定义而分裂；
- 函数地址唯一：所有 TU 中取 `&next_id` 得到同一个地址；
- C++11 起，函数内 static 局部变量的初始化是线程安全的（magic statics）。

## 9. inline 与 constexpr

```cpp
constexpr int square(int x) { return x * x; }   // constexpr 函数隐式 inline
```

- `constexpr` 函数**隐式**就是 inline 的（C++11 起），不需要再写 `inline`；
- 二者目的不同：`inline` 管「链接 + 建议展开」，`constexpr` 管「编译期可求值」；
- C++20 的 `consteval` 表示必须在编译期求值，也是隐式 inline。

## 10. 什么时候该用 inline

推荐：

- 1～3 行的小函数：getter/setter、`operator[]`、简单数学函数；
- 模板函数、类内定义的成员函数（它们本来就需要定义在头文件）；
- 性能热点上的小工具函数（配合 profile 验证）。

不推荐：

- 几百行的大函数：展开会造成代码膨胀、指令缓存压力、编译变慢；
- 到处给函数加 `inline`「求心安」：现代编译器自己会判断，加了也不会更快；
- 不要在 `.cpp` 里定义 inline 函数再给其他文件用。

## 11. 常见坑

1. **Debug 下不内联**：断点行为与 Release 不同，不要依赖 inline 调试；
2. **头文件里的普通函数重复定义**：缺少 `inline` 导致链接错误 `multiple definition`；
3. **inline 定义只在一个 .cpp 中**：其他 TU 调用时找不到定义；
4. **include guard 不能解决 ODR**：`#ifndef` 只防同一 TU 重复包含，不能防跨 TU 重复定义；
5. **递归/虚函数一般不会内联**；
6. **`inline namespace` ≠ inline 函数**，别混淆（见 [[命名空间]]）；
7. **`inline` 与宏混用**：宏仍需注意括号和副作用。

## 12. 小结

- `inline` = 建议内联 + 允许头文件中出现多份相同定义；
- 小函数、访问器、模板代码适合 inline；大函数交给编译器优化；
- 头文件定义普通函数必须加 inline，否则链接错误；
- C++17 的 inline 变量解决了头文件定义变量的问题；
- 记得区分 `inline function`、`inline variable`、`inline namespace` 三个东西。
